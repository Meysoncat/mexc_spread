# Архитектура

```
 биржи ──WS/REST──▶ MarketHub ──view()──▶ SetupEngine ──▶ SetupRegistry ──▶ события
 (11 шт.)           (память)              (детекторы)      (жизненный цикл)   │
                                                                              ├─▶ SSE / WS / REST (/api/v1)
                                                                              ├─▶ SQLite-журнал (история, исходы)
                                                                              └─▶ UI (одно SSE-подключение)
```

Один процесс FastAPI. Сетевой ввод-вывод изолирован в фоновых потоках хаба.
Детекторы и API работают только с памятью, поэтому медленная биржа не
тормозит ни генерацию, ни ответы.

## 1. MarketHub (`mexc_monitor/hub/`)

Единое рыночное состояние. `view()` за несколько миллисекунд собирает срез
`MarketView`, где лежат котировки perp и спота, сгруппированные по базовому
активу.

| Источник | Как | Частота |
|---|---|---|
| Лучшие bid/ask perp: Binance, Bybit, OKX, Gate, Bitget, HTX | WS-фиды `mexc_monitor/ws_bookticker.py` (общие с `/api/snapshot`) | пуш |
| dYdX | WS `v4_orderbook`, локальные книги (`mexc_monitor/dydx/ws_feed.py`) | пуш |
| MEXC perp | REST `contract/ticker`: в WS-тикере нет bid/ask | 1.5 с |
| Aster / Hyperliquid / Lighter | REST (у Hyperliquid — impact-цены, помечены `indicative`) | 2 / 2 / 10 с |
| Funding, OI, объём 24ч | REST, массовые эндпоинты; OI Binance — порциями по символам | 30–60 с |
| Справочник контрактов | REST: размер контракта, множитель, статус, интервал funding | 30 мин |
| Спот | REST, массовые эндпоинты | 3 с |
| 1m-свечи | WS kline (Binance, Bybit, MEXC) для топ-N по объёму, история по REST | пуш |

Нормализация (`hub/symbols.py`, `hub/hub.py`):
- символ → базовый актив и множитель цены: `1000PEPEUSDT` и `kPEPE` → PEPE ×1000;
- количество в стакане → монеты через размер контракта (OKX `ctVal`, Gate `quanto_multiplier`, HTX/MEXC `contract_size`);
- неактивные и делистингованные контракты отбрасываются;
- котировка считается устаревшей, если WS молчит больше 10 с или REST-ответ старше трёх интервалов опроса.

Каждая REST-задача независима: при ошибке включается экспоненциальный
backoff, состояние видно в `/api/v1/health`. Объём на лучшей цене для MEXC
догружается по запросу детектора (L1 probe) только для кандидатов в сетапы.

## 2. SetupEngine и детекторы (`mexc_monitor/setups/`)

Цикл раз в 0.5 с: `view()` → детекторы → `registry.sync()` → `registry.track()`.

- **Быстрые** (каждый такт): `cross_perp`, `lead_lag`; `basis` — раз в 2 с.
- **Funding** (раз в 10 с): `funding_arb`, `funding_squeeze`.
- **На свечах** (раз в 5 с): `breakout`, `momentum`, `btc_lag`.

Детектор — функция «срез → кандидаты» без побочных эффектов (кроме
внутренних EWMA-базлайнов). Пороги и комиссии берутся из
`config/setups.json`. У каждого порога есть пара `open_*` / `keep_*`:
это гистерезис, чтобы идея не «мигала».

Модель edge для арбитража: ожидаемая прибыль в bps от номинала ноги
- после taker-комиссий входа и выхода обеих ног,
- после пересечения спреда на выходе,
- за вычетом обычной разницы цен этих площадок (EWMA за 30–60 мин).

Устойчивая премия одной биржи поэтому не выдаётся за возможность.

## 3. SetupRegistry

- Открывает идею, когда кандидат держится `min_persist_sec`. Обновляет при заметном изменении (не чаще 1 с) и раз в 15 с как heartbeat.
- Арбитражную идею закрывает, если кандидата нет дольше `grace_sec`. Направленную — по стопу, цели или сроку, с записью исхода (`r_multiple`, MFE/MAE).
- После закрытия действует cooldown.
- События нумеруются (`seq`) и хранятся в кольцевом буфере на 10 000 событий для дочитки потоков. Через подписчиков они уходят в SQLite (`SetupStore`) и в API (`Broadcaster` → asyncio-очереди).

## 4. API (`backend/`)

- `backend/api_v1.py` — контракт для внешних систем (см. [INTEGRATION.md](INTEGRATION.md)).
- `backend/screener.py` — рантайм: хаб, движок, журнал, рассылка. Медленный подписчик переполняет свою очередь и отключается, не тормозя движок.
- `backend/main.py` — приложение FastAPI. Помимо v1 в нём старые эндпоинты Spread Monitor: `/api/snapshot`, `/api/klines`, `/api/depth`, `/api/spread/*`. Все SSE асинхронные и не занимают потоки пула.

## 5. Фронтенд (`frontend/`)

React + Vite + TypeScript + Tailwind:
- «Сетапы» и алерты — одно SSE-подключение на приложение (`setups/SetupStreamContext.tsx`), события применяются пачкой раз в 300 мс;
- «Скринер» — опрос `/api/v1/screener` раз в 3 с;
- «Spread Monitor» — подробная таблица одной биржи, грузится лениво.

## 6. Тесты

`pytest tests` покрывает:
- разбор ответов каждой биржи на образцах;
- нормализацию символов и сборку среза;
- каждый детектор на сконструированных рыночных ситуациях;
- жизненный цикл реестра;
- API: REST, SSE со снимком и дочиткой, WebSocket, ключ доступа.

`scripts/demo_market.py` запускает всё на синтетическом рынке.
