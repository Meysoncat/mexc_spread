## 0. Главное: это ДРУГАЯ стратегия, не «классический маркет-мейкинг»

В `docs/COIN_SELECTION_CRITERIA.md` я опирался на quant-литературу
(Avellaneda-Stoikov, Keyrock, DWF) — это **профессиональный институциональный
MM**. ProBoyScalp делает **совершенно другую вещь**, и **перечёркивает часть
моих критериев**. Это надо явно проговорить.

### В чём метод ProBoyScalp принципиально отличается

| | Классический MM (мой framework) | ProBoyScalp |
|---|---|---|
| **Где зарабатывает** | На захвате естественного bid/ask спреда пассивными лимитками | На **неэффективностях стакана** низколиквидных монет: плотности, завалы, прострелы, разрывы |
| **Что за активы** | Ликвидные пары с умеренной волатильностью | **Low-cap MEXC-альты с пустым стаканом** — где нет маркет-мейкера и есть «дыры» |
| **Что ищет** | Stable, ranging, high-volume | **Свежие листинги + «топы роста/падения»** с активной лентой принтов |
| **Ключевой сигнал** | σ, объём, maker share | **Стакан**: плотности (1-2k+ USDT), завалы, прострелы, разрывы между bid и ask |
| **Когда заходит** | Когда спред широкий и устойчивый | Когда **видит конкретного «участника» (алгоритм)** в стакане: переставляет плотности, прокидывает по рынку |
| **Боковик vs тренд** | Боковик обязателен | «И в боковике, и по тренду — неважно» (ProBoy) |
| **Stop-loss** | Стоп по времени/цене | **Без стоп-лосса** — выходить руками В плотность (MEXC не исполняет стопы на неликвиде) |
| **Депозит** | Любой | **До $500 специально**, можно с $10 |

### Вывод: мой framework был оптимизирован под неправильную стратегию

Я оценивал твою историю через линзу **Avellaneda-Stoikov MM** и нашёл, что
твои OSMO/TROLLSOL «неторгуемы». **Но ProBoyScalp эти пары как раз и не
торгует** — он ищет не волатильные пары, а пары **с пустым стаканом и
плотностями**. Твои плюсующие пары (LYN, GUA, VIM) — это, видимо, как раз
«алгосные» пары, где работал участник, а проигравшие (OSMO и т.д.) — трендовые
монеты без пустого стакана.

Это меняет интерпретацию твоего аудита — см. §4 ниже.

## 1. Что ProBoyScalp говорит про отбор монет (его критерии)

### 1.1. Источник кандидатов (где искать)

1. **Раздел «Спотовая торговля» на самой MEXC** → сортировка по
   **топам роста и топам падения**. Активные монеты = кандидаты.
2. **MEXC → вкладка «Новые листинги»** — только что добавленные.
3. **Свежие листинги на нескольких биржах одновременно**:
   - Colibri Telegram-канал — ежедневная сводка листингов по всем биржам
   - **ME / Gate / BingX** суммарно листят 10-15 инструментов в день
4. **Лучшие биржи под стратегию**: MEXC (~2500-3000 монет), Gate, BingX
   - **Binance / Bybit сразу нет** — слишком ликвидные, спреда нет
   - **Bitget / KuCoin — мало листингов**

### 1.2. Критерий отбора (не объём — а стакан)

> «Не сильно важно какой там объём. Главное — чтобы в стакане были
> неэффективности: плотности и спред.» — ProBoy, «50$ в день»

Конкретные фильтры по стакану:

| Что смотреть | Порог / признак |
|---|---|
| **Кластерный объём за 15 мин** | **≥ 5-10k USDT** (если меньше — «теряете время») |
| **Плотности в стакане** | ≥ **1-2k USDT** считаются «крупными» (зависит от ликвидности) |
| **Прострелы** | По теням свечей видны частые прострелы → алгоритм работает |
| **Поведение участника** | Кто-то прокидывает по рынку, переставляет лимитки → «есть алгос» |
| **Разрыв (спред)** | Пустое пространство между лучшим bid и лучшим ask |
| **Пустоты между плотностями** | Между двумя плотностями нет заявок → «разрыв спреда» |

### 1.3. Графики, которые он ищет (форма движения)

ProBoy описывает **характерный паттерн «алгоритма»** — монеты, на которых
кто-то систематически гоняет:

- **Паттерн 1**: памп-дамп-памп-дамп в одном диапазоне (алгоритм накапливает
  позу, пампит, скидывается, снова накапливает)
- **Паттерн 2**: «жирный» малоликвидный алгоритм — быстро набирает, быстро
  закрывает, ходит в узком диапазоне
- **Ключевое**: «алгоритм всегда ходит в одном диапазоне»

Это **не боковик Avellaneda-Stoikov** — это **осознанное поведение конкретного
«участника»**, которого надо заметить в стакане.

### 1.4. RED FLAGS — что НЕ торговать

| Что | Почему |
|---|---|
| Совсем неликвид, где продажа на $50 двигает цену на 10%+ | Нельзя выйти |
| Сильно падающие монеты | «Большой элемент рандома» |
| «Накрученные» пампы без реального объёма | Симуляция объёма |
| Плотности, которые «мерцают» (постоянно появляются/исчезают) | **Спуфер**, маркет-мейкер создаёт видимость; реальные деньги там не стоят |

## 2. Его 6 видов сбора спреда (механика исполнения)

Это **конкретный actionable playbook** — намного практичнее, чем что-либо в
quant-литературе:

| # | Сценарий | Что делать |
|---|---|---|
| 1 | От ближайшей крупной плотности (≥1-2k USDT) | Выставить лимитки **каскадом** до лучшей цены продажи. Если плотность съедают — выйти в неё. |
| 2 | От завала небольших плотностей (500-600 USDT) | Тот же заход, если нет крупной плотности |
| 3 | От плотности, после которой есть разрыв до следующей | Прогноз: если съедят первую → цена ударится во вторую → забрать разрыв |
| 4 | **На листингах**: лента активная, цена подходит к плотности | Зайти в «разъедание», выставить лимитки на продажу в пустое пространство после плотности |
| 5 | Активная лента + большой разрыв (без плотностей) | Опасно — но если лента активная, высока вероятность исполнения. Быстро выходить, когда активность затухает. |
| 6 | **Халява**: в разрыв вставляется крупная плотность | Стоять, пока плотность не начнут есть → участник-переставщик толкает разрыв дальше |

### Принцип набора позиции — **каскад лимиток**

> «Делим позу на 3, ставим три лимитки каскадом. Если бы поставили одну —
> прострел бы нас не забрал. С тремя — забрало бы две, мы стояли бы на 66%.»

Это **inventory risk management через усреднение по уровням** — твоему
`SpreadCaptureEngine` этого пока нет.

## 3. Безопасность / риск по ProBoy

| Правило | Обоснование |
|---|---|
| **Без стоп-лосса** | MEXC на неликвиде стопы не исполняет — «даже не пытайтесь» |
| **Выход только руками** | В плотность, когда её начинают есть, или когда цена идёт против |
| **Депозит ≤ $500** | Так задумано; на больших капиталах стратегия не масштабируется |
| **Без кредитных плеч** | Только спот |
| **20-40 стаканов одновременно** | Ситуации могут возникать в любой момент |
| **«Пыль» (остатки < $10) → в MX-токен → конвертация** | Мелочь, но иначе мёртвый остаток |

## 6. Обновлённый фреймворк отбора (ProBoy + quant)

Я объединяю свой первоначальный framework (quant-литература) с практикой
ProBoyScalp. **Корректный чек-лист для твоей стратегии (сбор спреда на
алгоритмах MEXC):**

### MUST-HAVE (от ProBoyScalp, первичны)

1. **Кластерный объём за 15 мин ≥ 5-10k USDT** — иначе «теряете время».
2. **Плотности в стакане ≥ 1-2k USDT** — есть что использовать как точку
   выхода и точку отсчёта для лимиток.
3. **Пустой стакан с разрывом спреда** — главное условие: нет MM, который
   уже собрал бы спред.
4. **Видимый «участник»** в стакане — кто-то прокидывает по рынку или
   переставляет лимитки. Без него торговать бесполезно.
5. **Не «накрученная» монета** — реальные принты в ленте, не только
   симуляция.

### MUST-HAVE (от quant-литературы, остаются в силе)

6. **Maker share ≥ ~75% как kill-switch** (на MEXC 0/5bps это абсолют).
7. **Твой ордер ≤ 5-10% top-5 depth** (чтобы не двигать рынок).

### NICE-TO-HAVE

8. **Свежий листинг или топы роста/падения** (по ProBoy).
9. **Биржи MEXC / Gate / BingX** (остальные слишком ликвидные).
10. **Не в моменте сильного однонаправленного тренда** (хотя ProBoy
    допускает тренд, если есть участник).

### HARD NO

- **Полностью неликвидная** (продажа на $50 двигает цену на 10%+).
- **Спуферные плотности** (мерцают, исчезают).
- **Плотное падение без откатов** (большой элемент рандома).
- **Maker share в live упал ниже 70%** — тебя adversely select'ят.

## 7. Что ProBoyScalp НЕ рассказывает (и где твой код может быть сильнее)

1. **Количественные пороги** он даёт на уровне «1-2k USDT», «5-10k за 15 мин»,
   но не точные формулы. Тут твой `density.py`, `density_buffer.py`,
   `vwap.py`, `SlippageEstimator.tsx` могут дать **более точную математику**.

2. **Backtesting** у него нет вообще. У тебя есть `backtest.py` + история
   в SQLite + Quants Lab в Hummingbot. Можно прогнать метод ProBoy на
   своих исторических плотностях.

3. **Дисциплина исполнения** у него ручная (20-40 стаканов глазами).
   У тебя `MetaScalpAutoTrader` может алерты/автоторговлю.

4. **Риск-менеджмент** у него «выходить руками» — субъективно.
   Твой `risk.py` + kill-switch по maker share могут быть строже.

## 9. Реализованные детекторы (Вариант E)

В проекте реализован **полуручной вариант** стратегии (см.
`docs/STRATEGY_APPROACHES.md` §E): детекторы сигналов работают автоматически,
ордера — руками через MetaScalp.

### Что реализовано

| Компонент | Файл |
|---|---|
| Density scanner (стакан MetaScalp → стены + статистика) | `mexc_monitor/metascalp/density_scanner.py` |
| Participant detector (всплески market-ордеров) | `mexc_monitor/metascalp/participant_detector.py` |
| Signal worker (фоновый скан watchlist + алерты) | `mexc_monitor/metascalp/signal_worker.py` |
| WS-подписка на trades → participant detector | `mexc_monitor/metascalp/ws_bridge.py` (subscribe_trades) |
| Telegram-алерт на комбинированный сигнал | `mexc_monitor/alerts/service.py` (send_density_signal) |

Переиспользованы **без изменений**:
- `mexc_monitor/density.py` — exchange-agnostic, detect_walls + compute_density_stats
- `mexc_monitor/density_buffer.py` — ring buffer истории стен

### Конфигурация

Файл `config/metascalp_signals.json`:

```json
{
  "enabled": false,                    // Включить SignalWorker
  "conn_id": "",                       // Пусто = auto-resolve первого connection
  "watchlist": ["LYN_USDT", "..."],   // Тикеры для периодического скана
  "interval_sec": 10.0,                // Как часто сканить
  "min_notional_usdt": 1000,           // Мин. размер стены (ProBoy: 1-2k)
  "multiplier": 5.0,                   // Аномальность относительно медианы
  "min_spread_bps": 5,                 // Мин. спред чтобы считать кандидатом
  "alert_min_walls": 1,                // Мин. стен для алерта
  "alert_min_participant_vol": 1000,   // Мин. USDT участника для алерта
  "spike_threshold_usdt": 1000,        // Всплеск за 60с = участник
  "cluster_threshold_usdt": 5000,      // Кластер за 15м = сильный участник
  "domination_ratio": 0.65             // Доминация стороны для участника
}
```

Включить/выключить через API без рестарта:
```
POST /api/metascalp/signals/config
{"enabled": true, "watchlist": ["LYN_USDT", "GUA_USDT"]}
POST /api/metascalp/signals/reload
```

### Использование

1. **Запустить MetaScalp** (десктоп-приложение с подключённым MEXC).
2. **Старт backend** (`run_modern.bat` или `python -m uvicorn backend.main:app`).
3. **Подписаться на trades** для тикеров watchlist (иначе participant detector
   будет пустым):
   ```
   POST /api/metascalp/trades/subscribe
   {"conn_id": "...", "tickers": ["LYN_USDT", "GUA_USDT"]}
   ```
4. **Включить SignalWorker** (см. конфиг выше).
5. **Смотреть сигналы** в UI: `MetaScalpPage` → блок «Density Signals».
6. **Telegram-алерты** приходят автоматически при комбинированных сигналах
   (плотности + участник), если `density_signals_enabled=true` в
   `config/alerts.json`.
7. **Ордера — руками** в MetaScalp по увиденному сигналу.
