# Прокси через VLESS (Xray-мост)

Как использовать **VLESS**-прокси для обхода геоблокировок бирж (Binance `451`,
MEXC market-data REST закрыт для IP дата-центра).

## Зачем нужен мост

Наш HTTP-стек (`httpx`) и валидатор прокси понимают только схемы
`http` / `https` / `socks5` / `socks5h`. **VLESS напрямую вписать нельзя** — это
транспорт Xray/V2Ray (обычно поверх TLS/Reality/WebSocket), который `httpx` не
умеет. Поэтому рядом поднимается локальный **Xray-клиент**: VLESS как outbound,
локальный SOCKS5 как inbound. Приложение ходит на обычный `socks5h://…`, а Xray
уже туннелирует трафик через VLESS в нужную юрисдикцию.

```
приложение (httpx) → socks5h://127.0.0.1:10808 → [Xray: VLESS outbound] → биржа
```

> **Smart DNS (напр. xbox-dns.ru) тут не поможет** — он лишь меняет резолв
> whitelisted доменов и не меняет исходящий IP дата-центра. Нужен именно
> egress-прокси с IP в разрешённом регионе.

## Что уже есть

- `scripts/xray_bridge.py` — поднимает мост (парсит VLESS-ссылку, генерирует
  конфиг Xray, скачивает бинарь Xray-core под платформу, запускает, опционально
  тестирует выход).
- Приложение уже умеет per-exchange прокси: env `MEXC_HTTP_PROXY[_<БИРЖА>]`,
  страница **Сеть / Прокси** (`/network`), API `GET/PATCH /api/network/config` и
  `GET /api/network/test?exchange=<name>`. См. `docs/DATA_SOURCES.md`.
- Зависимости для SOCKS уже стоят (`socksio` для httpx). Отдельно ставить нечего.

## Быстрый старт

```bash
# 1. Ссылку — через env, чтобы не светить UUID в history шелла
export XRAY_VLESS_URL="vless://<uuid>@host:443?security=reality&type=tcp&sni=...&pbk=...&sid=...&flow=xtls-rprx-vision#name"

# 2. Поднять мост и сразу проверить выход (egress IP + доступность MEXC/Binance)
python scripts/xray_bridge.py --test

# → ✅ Мост поднят. Прокси: socks5h://127.0.0.1:10808
#   🌍 Egress IP через прокси: <IP в разрешённом регионе>
#   ✅ MEXC spot: HTTP 200   ✅ Binance spot: HTTP 200
```

Скрипт скачает Xray-core в `.xray/bin/` (эта папка в `.gitignore`) при первом
запуске. Если бинарь уже есть — задайте `XRAY_BIN=/path/to/xray` или положите в
`PATH`, и скачивание пропустится (`--no-download` запретит его совсем).

## Подключить прокси к приложению

Мост даёт `socks5h://127.0.0.1:10808`. Дальше любой из способов:

**Вариант А — env-переменные** (удобно на деплое; см. `docs/DATA_SOURCES.md`):

```bash
# только геоблокированным биржам; остальные оставляем direct
export MEXC_HTTP_PROXY_BINANCE="socks5h://127.0.0.1:10808"
export MEXC_HTTP_PROXY_MEXC="socks5h://127.0.0.1:10808"
# либо общий прокси для всех:
# export MEXC_HTTP_PROXY="socks5h://127.0.0.1:10808"
```

**Вариант Б — страница «Сеть / Прокси»** (`/network`): вписать
`socks5h://127.0.0.1:10808` в переопределение для нужной биржи и нажать проверку.
Меняется в рантайме, без рестарта.

> Используйте `socks5h` (а не `socks5`) — суффикс `h` резолвит DNS на стороне
> прокси, что важно, если сам DNS тоже фильтруется.

## Важно: прокси касается только REST/HTTP

- Прокси-стек применяется к **HTTP-запросам** (`httpx`): снапшоты бирж по REST,
  REST-fallback для density, `contract/detail` и т.п.
- **WS-фиды идут напрямую, мимо прокси** (`websocket.create_connection` без
  proxy). Это осознанно: WebSocket у бирж **не геоблокируется** — ради этого и
  сделаны фиды глубины/цен по WS (`ws_futures_depth_book.py` и др.). Гонять WS
  через мост не нужно.
- Если однажды понадобится проксировать и WS (напр. биржа заблокирует WS), это
  отдельная доработка: параметры `http_proxy_host`/`proxy_type` у
  `create_connection` + пакет `python_socks`.

## Проверка

```bash
# egress IP и доступность бирж прямо через мост
python scripts/xray_bridge.py --test

# через API приложения (после того как прописали прокси бирже)
curl "http://127.0.0.1:8006/api/network/test?exchange=binance"
# → {"reachable": true, "status": 200, "proxy": "socks5h://127.0.0.1:10808", ...}

# реальный путь данных — снапшот должен ожить и вернуть source, а не пустоту
curl "http://127.0.0.1:8006/api/snapshot?exchange=binance&market=spot"
```

## Полезные флаги

| Флаг | Назначение |
| --- | --- |
| `--url "vless://…"` | Ссылка аргументом (вместо env `XRAY_VLESS_URL`) |
| `--url-file path` | Прочитать ссылку из файла (одна строка) |
| `--socks-port 10808` | Порт SOCKS5 inbound |
| `--http-port 10809` | Порт HTTP inbound (`0` — отключить) |
| `--print-config` | Только показать сгенерированный конфиг Xray и выйти |
| `--test` | После запуска проверить выход (egress IP + биржи) |
| `--no-download` | Не скачивать Xray автоматически |
| `XRAY_BIN=/path` | Использовать готовый бинарь Xray |
| `XRAY_DIR=.xray` | Куда класть бинарь и конфиг |

Поддерживаемые транспорты VLESS: `tcp` (в т.ч. `headerType=http`), `ws`, `grpc`,
`http/h2`; security: `none`, `tls`, `reality`, `xtls` (`flow` пробрасывается).

## Безопасность

- **VLESS-ссылка содержит секрет (UUID).** Передавайте её через
  `XRAY_VLESS_URL` или `--url-file`, а не аргументом — иначе она осядет в history
  шелла и в списке процессов.
- Сгенерированный `.xray/config.json` тоже содержит UUID; папка `.xray/` уже в
  `.gitignore` и пишется с правами `600`. Никогда не коммитьте её.
- Мост слушает только `127.0.0.1` — не выставляйте порт наружу без
  аутентификации.

## Траблшутинг

- **`Бинарь Xray не найден`** — уберите `--no-download`, либо задайте `XRAY_BIN`,
  либо положите `xray` в `PATH`.
- **`SOCKS-порт не открылся`** — порт занят (смените `--socks-port`) или Xray
  упал: посмотрите его вывод (скрипт печатает лог с префиксом `[xray]`).
- **`Недопустимая схема прокси`** от приложения — используйте `socks5h://…`,
  а не `vless://…`. VLESS идёт только в мост, приложению — уже SOCKS.
- **Биржа всё ещё блокирует** — проверьте `--test`: если egress IP всё ещё в
  заблокированном регионе, проблема на стороне VLESS-сервера (не тот выходной
  узел), а не в мосте.
